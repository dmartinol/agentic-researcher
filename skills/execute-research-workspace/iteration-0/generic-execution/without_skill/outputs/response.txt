RESEARCH QUESTION: Does MCP support server-side tool discovery?

ANSWER: YES - MCP (Model Context Protocol) fully supports server-side tool discovery.

================================================================================
DETAILED FINDINGS
================================================================================

1. PRIMARY DISCOVERY MECHANISM: tools/list ENDPOINT
   ------------------------------------------------
   - MCP servers expose tools through the `tools/list` JSON-RPC endpoint
   - Clients call this endpoint to discover all available tools from a server
   - The endpoint returns a paginated list of tools with their schemas

   Request Format:
   {
     "jsonrpc": "2.0",
     "id": 1,
     "method": "tools/list",
     "params": {
       "cursor": "optional-cursor-value"
     }
   }

   Response includes:
   - Tool name
   - Tool description
   - Input schema (JSON Schema format)
   - Optional output schema

2. INITIALIZATION & CAPABILITY NEGOTIATION
   ----------------------------------------
   - When a client connects to an MCP server, it sends an `initialize` request
   - The server responds with its capabilities, including:
     * Available tool endpoints
     * Resource endpoints
     * Prompt endpoints
     * Protocol version
     * Server information

   - The 2025-06-18 specification update formalized this process:
     * Client sends: protocolVersion, capabilities, clientInfo
     * Server responds: serverInfo, protocolVersion, capabilities, instructions

3. RUNTIME DISCOVERY
   ------------------
   - MCP is designed for runtime discovery, not hardcoded connections
   - AI systems can dynamically:
     * Query available tools
     * Understand tool capabilities through structured schemas
     * Invoke tools with proper parameters

   - This makes MCP particularly valuable for building flexible, runtime-adaptable
     AI systems that work with various external services without requiring custom
     integrations for each pairing

4. SERVER DISCOVERY PROTOCOL (.well-known endpoints)
   -------------------------------------------------
   - Two Specification Enhancement Proposals (SEPs) emerged in 2025:

   a) SEP-1649: Server Card Discovery
      - Defines /.well-known/mcp/server-card.json
      - Contains human-readable description, homepage
      - Includes full tool/resource/prompt listings
      - Aimed at catalogs and human users

   b) SEP-1960: MCP Discovery Endpoint
      - Filed December 11, 2025
      - Defines standardized /.well-known/mcp endpoint
      - Provides server metadata discovery
      - Includes capability advertisement
      - Contains security policy declarations

   - As of mid-2026, recommendation is to serve both static JSON files
   - Claude Desktop probes these endpoints to determine transport and capabilities
     before connecting

5. PROTOCOL ARCHITECTURE
   ----------------------
   - Built on JSON-RPC 2.0
   - Supports multiple transport methods:
     * stdio (standard input/output)
     * HTTP POST
     * Server-Sent Events (SSE)

   - Discovery methods include:
     * tools/list - List available tools
     * resources/list - List available resources
     * prompts/list - List available prompts

   - All list methods support pagination with nextCursor tokens

6. TOOL INVOCATION PROCESS
   ------------------------
   After discovery, tools are invoked via:
   - Endpoint: tools/call
   - Server performs the requested operation
   - Returns results to the client
   - Each tool has structured input/output schemas

7. BENEFITS OF SERVER-SIDE DISCOVERY
   ----------------------------------
   - No need to hardcode connections to each external service
   - AI agents can dynamically discover available tools
   - Understand capabilities through structured schemas
   - Invoke tools with proper permissions
   - Enables building flexible, adaptable AI systems
   - Supports runtime changes to available tools
   - Facilitates tool sharing and reuse across different AI systems

================================================================================
CONCLUSION
================================================================================

MCP comprehensively supports server-side tool discovery through multiple mechanisms:

1. Primary: tools/list JSON-RPC endpoint for runtime discovery
2. Secondary: Initialization handshake for capability negotiation
3. Optional: .well-known discovery endpoints for server metadata
4. Structured: JSON Schema-based tool definitions
5. Dynamic: Runtime-adaptable without hardcoded connections

The protocol is specifically designed to enable AI systems to discover and utilize
tools dynamically, making it a robust solution for server-side tool discovery in
AI agent architectures.
