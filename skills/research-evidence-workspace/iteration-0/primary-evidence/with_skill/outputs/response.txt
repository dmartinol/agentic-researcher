# Research Evidence Report: MCP Specification Server-Side Sampling Support

## Research Question

Does the current MCP (Model Context Protocol) specification support server-side sampling capability? What claims can be cited in an architecture decision?

Retrieved: September 22, 2026

## Executive Summary

Server-side sampling is **DEPRECATED but still functional** in the current MCP specification (version 2026-07-28). While the feature remains operational and supported until at least July 28, 2027, new implementations should NOT adopt it and should instead integrate directly with LLM provider APIs.

### Claim 4: Definition of Sampling Capability
**Statement:** Sampling in MCP allows servers to request LLM sampling ("completions" or "generations") from language models via clients, enabling servers to implement agentic behaviors without requiring server API keys.

**Evidence Label:** Verified

**Supporting Evidence:**
- Source: Official MCP Specification Sampling page (https://modelcontextprotocol.io/specification/draft/client/sampling)

### Claim 5: Reason for Deprecation
**Statement:** Sampling was deprecated because it relied on constantly open bidirectional streams, which conflicts with MCP's evolution toward a stateless protocol architecture.

**Evidence Label:** Verified

**Supporting Evidence:**
- Source: MCP Blog (https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- Evidence: "The sampling mechanism relied on 'constantly open bidirectional streams,' which conflicted with MCP's evolution toward a stateless protocol architecture."
- Context: The 2026-07-28 specification removes protocol-level session tracking, making MCP stateless at the protocol layer
- Observation Time: September 22, 2026

**Qualifications:** This is the stated architectural rationale from official sources.

### Claim 7: Replacement Technology
**Statement:** Multi Round-Trip Requests (MRTR) replaces the deprecated sampling functionality, enabling stateless request-response patterns where servers can request user input mid-call.

**Evidence Label:** Verified

## Conclusion

**Direct Answer to Research Question:**

The current MCP specification (version 2026-07-28) **does not actively support** server-side sampling as a recommended feature. While sampling is technically functional and will remain in the specification until at least July 28, 2027, it is officially deprecated (SEP-2577).

**Architecture Decision Guidance:**

For new implementations: **Do NOT use MCP sampling.** Instead, integrate directly with LLM provider APIs for sampling/completion capabilities.

For existing implementations using sampling: **Plan migration** to direct LLM provider API integration within the 12-month deprecation window.

For server-to-client communication needs: Consider Multi Round-Trip Requests (MRTR) as the stateless replacement pattern.
